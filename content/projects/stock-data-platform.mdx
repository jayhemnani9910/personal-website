  keyDecisions:
    - decision: "TimescaleDB over plain Postgres"
      reasoning: "Decades of daily prices across 10 tickers plus hourly bars and macro series is time-series-heavy; TimescaleDB hypertables keep range queries fast while staying SQL-native."
      tradeoff: "One more extension to operate versus reaching for a dedicated TSDB like InfluxDB and losing relational joins to the dimension tables."
    - decision: "Batch-and-flush Kafka consumer, not per-message inserts"
      reasoning: "Upserting in batches of 50 (or every 10s, whichever comes first) cuts write amplification and keeps the warehouse current without hammering it."
      tradeoff: "A small bounded staleness window in exchange for far fewer transactions."
    - decision: "Incremental DAGs keyed on last-loaded date"
      reasoning: "Each ETL run reads the latest date already in the warehouse and re-reads only a 10-day overlap from there, so reruns are idempotent and late provider corrections are picked up; the first run loads the full history."
      tradeoff: "More bookkeeping per DAG than a naive full reload."

        def _normalize_columns(df, ticker):
            """Map yfinance columns (with or without ticker suffix) to open/high/low/close/volume."""
            if isinstance(df.columns, pd.MultiIndex):
                df.columns = ["_".join(col) for col in df.columns]
            col_map = {}
            for std in ["Open", "High", "Low", "Close", "Volume"]:
                suffixed = f"{std}_{ticker}"
                if suffixed in df.columns:
                    col_map[suffixed] = std.lower()
                elif std in df.columns:
                    col_map[std] = std.lower()
            return df.rename(columns=col_map)

        # re-read a short overlap from the last loaded date -> reruns are idempotent;
        # the first run has no last date and takes the full history

Combines 4 data sources (yfinance prices, SEC EDGAR filings, FRED macro indicators, and Alpaca hourly bars) through a live Kafka stream and 23 Airflow DAGs into a 10-table star schema on TimescaleDB, shown on a Chart.js dashboard.
