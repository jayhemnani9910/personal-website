  keyDecisions:
    - decision: "TimescaleDB over plain Postgres"
      reasoning: "Decades of daily prices plus hourly bars and macro series is time-series-heavy. Hypertables split those tables into time chunks, and it's still SQL, so joins to the dimension tables keep working."
      tradeoff: "One more extension to run. A dedicated time-series database like InfluxDB would have cost me the relational joins."
    - decision: "Batch and flush in the Kafka consumer, no per-message inserts"
      reasoning: "It upserts every 50 messages or every 10 seconds, whichever comes first. That means far fewer transactions, and the warehouse stays close to current."
      tradeoff: "Data can wait in the batch for about 10 seconds."
    - decision: "Incremental DAGs keyed on last-loaded date"
      reasoning: "Each run finds the latest date in the warehouse and re-reads 10 days from there, so reruns are safe and late corrections get picked up. If those 10 days no longer match what's stored, a dividend or split has re-adjusted the history, and it reloads the whole series so prices don't step at the boundary. The first run loads everything."
      tradeoff: "More bookkeeping per DAG than a plain full reload, and spotting those re-adjustments is easy to get wrong. My first check missed an NVDA dividend and left 6,949 closes 0.11% high until I fixed it."

        def _connect_kafka():
            for attempt in range(1, MAX_RETRIES + 1):
                try:
                    consumer = KafkaConsumer(
                        KAFKA_TOPIC,
                        bootstrap_servers=[os.environ.get("KAFKA_BOOTSTRAP", "...:9092")],
                        auto_offset_reset="earliest",
                        group_id="stock-data-consumer",
                        value_deserializer=lambda m: json.loads(m.decode("utf-8")),
                    )
                    return consumer
                except Exception as e:
                    delay = min(BACKOFF_BASE * (2 ** (attempt - 1)), BACKOFF_CAP)
                    time.sleep(delay)
            raise ConnectionError(f"Failed to connect after {MAX_RETRIES} attempts")

        # batch by size OR time, whichever trips first
        if batch and (len(batch) >= BATCH_SIZE or now - last_flush >= FLUSH_INTERVAL):
            conn = _flush_batch(conn, batch)
            batch, last_flush = [], now
      explanation: "Exponential backoff on connect, then a flush on size or time, whichever trips first. A failed flush reconnects and retries once. If the retry fails too, that batch is discarded, so it survives a database blip but not a long outage."

        def _normalize_columns(df, ticker):
            """Map yfinance columns (with or without ticker suffix) to open/high/low/close/volume."""
            if isinstance(df.columns, pd.MultiIndex):
                df.columns = ["_".join(col) for col in df.columns]
            col_map = {}
            for std in ["Open", "High", "Low", "Close", "Volume"]:
                suffixed = f"{std}_{ticker}"
                if suffixed in df.columns:
                    col_map[suffixed] = std.lower()
                elif std in df.columns:
                    col_map[std] = std.lower()
            return df.rename(columns=col_map)

        # re-read a short overlap from the last loaded date -> reruns are idempotent;
        # the first run has no last date and takes the full history
        last_date = _get_last_loaded_date(ticker)
        if last_date:
            start_date = last_date - timedelta(days=OVERLAP_DAYS)
            df = _normalize_columns(yf.download(ticker, start=start_date, end=end_date, progress=False), ticker)

            df = _normalize_columns(yf.download(ticker, period="max", progress=False), ticker)

The clever part is how it handles history being rewritten. Each nightly run re-reads 10 days and compares them with what's stored. If they don't match, a dividend or split has re-adjusted the past, and it reloads the whole series so prices don't step at the boundary. Hourly bars get similar care: Alpaca's own hourly bars include pre- and post-market trading, so the loader fetches 30-minute bars and folds them into regular-session hours.
