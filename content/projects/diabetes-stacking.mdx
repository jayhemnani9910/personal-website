challenge: "PIMA looks simple: 768 patients, 8 measurements, diabetes yes or no. Look closer and 374 of those patients have an insulin reading of zero and 227 have zero skin thickness, which are missing values dressed up as numbers. On data that small and noisy, one classifier gets some patients right and another gets others. So we asked whether a meta-model could learn how to combine them and beat any one of them alone."
solution:
  - "Six base classifiers: Gaussian Naive Bayes, Random Forest, Decision Tree, SVM, an ANN (MLP) and Logistic Regression. Five are tuned with randomized search over 10-fold CV repeated 3 times. Naive Bayes keeps a fixed var_smoothing."
  - "The impossible zeros get replaced with the training-set mean, in every column except Pregnancies, where zero is a real answer. Logistic Regression, SVM and the ANN scale their features first."
  - "A scikit-learn StackingClassifier (cv=4) feeds the six models' predictions to a Random Forest meta-learner, on a 70/30 train/test split."

  keyDecisions:
    - decision: "Stacking rather than a single tuned model or simple voting"
      reasoning: "Different classifiers make different mistakes on small, noisy data. A meta-learner can learn how to weight them, where a vote can't. That was the hypothesis we set out to test."
      alternatives: "One well-tuned model (simpler, ignores what the others know); majority voting (combines them but can't learn the weights)."
    - decision: "Tune the base models before stacking"
      reasoning: "There's no point stacking weak defaults. Randomized search keeps tuning cheap across five models, and Naive Bayes has little to tune."
      alternatives: "Stack untuned defaults (weaker members); exhaustive GridSearchCV (far more expensive across five models)."
    - decision: "Fix the seeds and report the held-out number as it comes out"
      reasoning: "With 768 rows the result moves with the split and the seed. Before the seeds were fixed, the stack ranged from 72% to 77% across runs. Fixing them makes the number repeatable, and it goes on the page whichever way it lands."
      alternatives: "Report the best-looking run (misleading on small data); skip a held-out set (no honest estimate at all)."

The clever idea is that the models don't vote. A second model watches how each one does on data it didn't train on, then learns whose opinion to weigh and when. We built that as a team and published it, and the construction is still the part I like best. The repo keeps the whole thing in one notebook you can run yourself, with the current numbers at the top.
