challenge: "Ask one LLM to research something and it tends to confirm whatever it believed first. I wanted a system that tries to falsify its own claims: model the question as a causal graph, then attack each causal link with a dedicated adversary before trusting it."
solution:
  - "A LangGraph workflow called CAG (Causal-Adversarial Graph) plans a graph of cause-and-effect claims, then investigates each link with a red team agent hunting for counter-evidence and a blue team agent hunting for support."
  - "A separate judge weighs the two sides on scientific criteria and returns VERIFIED, FALSIFIED or UNCLEAR with a confidence score. Nobody argues and rules on the same claim."
  - "Search and LLM providers sit behind ports and adapters, so DuckDuckGo, Tavily, Exa, Groq and GitHub Models swap by config. The Ollama adapter is written but commented out of the container, so going local takes a small code change."

  - "The results are humbling. Across 33 saved reports, some of them smoke tests, 7 findings came back VERIFIED and 125 UNVERIFIED. On startup failure the judge called out blue team sources about Adderall and marketing. The scepticism works. The evidence gathering is the weak part."

deepDive:
  context: "Most LLM research tools hand you a confident synthesis and rarely an argument against it. Good research works the other way round: a claim earns trust after someone has tried to break it. CAG is built around that idea. It turns a question into a graph of hypothesized cause-and-effect links, and for each link it runs an adversary whose only job is to find contradicting evidence, next to a supporter looking for confirming evidence. A judge weighs both. You get a set of claims, each with a verdict and the evidence on both sides, rather than one narrative. It was built in 10 days from a rough problem statement."
  architecture: "It's a LangGraph state machine over a shared ResearchState, with a causal graph at the centre. The Causal Planner turns the query into hypothesized edges and the Edge Selector picks the next unresolved one. The Investigate step runs the Adversary and Supporter concurrently (asyncio.gather), writing to separate evidence buffers that custom reducers merge. The Dialectical Judge weighs both sides on credibility, recency, methodology, replication, effect size and confounders, then updates the graph with a typed verdict. The Auditor checks depth, visit counts and repeated actions before control returns to the Selector, and when no edges are left the Writer produces the report. Routing uses explicit Command(goto=...) returns, a workaround for hangs seen with LangGraph 1.0.x conditional edges. LLM, search and storage sit behind ports and get injected."

  keyDecisions:
    - decision: "Causal-adversarial (Popperian) design over a single-LLM synthesizer"
      reasoning: "Popper's idea, in code: every edge gets attacked by a dedicated adversary before it's accepted. That gives confident-but-wrong synthesis somewhere to get caught."
      tradeoff: "Far more LLM and search calls per question than a one-shot answer, which is why depth and per-edge investigations are capped."
    - decision: "Run adversary and supporter in parallel, then judge"
      reasoning: "Each edge gets both perspectives in one step via asyncio.gather, and a separate judge decides. No single agent both argues and rules."
      tradeoff: "Parallel writes need care: the two kinds of evidence go to separate buffers with custom LangGraph reducers so they don't clobber each other."
    - decision: "Command(goto=...) routing instead of conditional edges"
      reasoning: "LangGraph 1.0.x conditional edges hung in this environment, so nodes return an explicit Command(goto=...) to route. Boring, deterministic and easy to debug."
      tradeoff: "Routing lives in node wrappers rather than graph edges, so less of the graph is visible at a glance."
    - decision: "Hexagonal ports and adapters for search and LLMs"
      reasoning: "With search and models behind ports, development runs on free DuckDuckGo plus a free-tier LLM, and paid search or a different model pool is a config change. Mock adapters also give a smoke run with no keys at all."
      tradeoff: "More interface and adapter code up front than calling an SDK directly."

    - title: "The CAG graph: a falsification loop"
      language: "python"
      code: |
        class CAGGraphBuilder:
            """Causal-Adversarial Graph (CAG): a Popperian falsification engine.
            1. Planner   -> builds a causal DAG from the query
            2. Selector  -> picks the next edge to investigate
            3. Adversary + Supporter -> parallel red / blue research
            4. Judge     -> resolves the conflict, updates the graph
            5. loop to Selector until edges resolve or max depth
            6. Writer    -> synthesizes the final report
            """
            def build(self) -> StateGraph:
                wf = StateGraph(ResearchState)
                wf.add_node("planner", self._run_planner)
                wf.add_node("auditor", self._run_auditor)
                wf.add_node("selector", self._run_selector)
                wf.add_node("investigate", self._run_parallel_investigation)
                wf.add_node("judge", self._run_judge)
                wf.add_node("writer", self._run_writer)
                wf.add_node("error_handler", self._handle_error)
                wf.add_edge(START, "planner")
                wf.add_edge("planner", "auditor")
                wf.add_edge("investigate", "judge")
                wf.add_edge("judge", "auditor")
                wf.add_edge("writer", END)
                # routing via Command(goto=...) inside nodes: a deliberate
                # workaround for LangGraph 1.0.x conditional-edge hangs
                return wf.compile()
      explanation: "The whole engine in one place. Look for the unflattering comment: conditional edges hung on this LangGraph version, so the auditor and selector route by returning Command(goto=...) instead."
    - title: "Red team + blue team, in parallel"
      language: "python"
      code: |
        async def _run_parallel_investigation(self, state):
            """Adversary (red) and Supporter (blue) research the same edge at once."""
            adversary, supporter = await asyncio.gather(
                self._run_adversary(state),   # hunts contradicting evidence
                self._run_supporter(state),   # hunts supporting evidence
            )
            return {
                "contradicting_evidence": adversary.get("contradicting_evidence", []),
                "supporting_evidence":    supporter.get("supporting_evidence", []),
                # node_visit_counts / action_hashes merged via state reducers
            }
      explanation: "Starting two agents is one line. Merging what they write without losing half of it is the tricky bit, and that's what the separate buffers and custom reducers are for."

  learnings:
    - "An adversary and a judge are only as good as what search brings back. My saved reports mostly end in UNVERIFIED, often because the evidence was off-topic. That's still better than a tidy wrong answer."
    - "Parallelism is easy. Merging parallel state isn't. asyncio.gather took a line, and keeping the concurrent writes intact took custom reducers and separate buffers."

The idea is old: Popper said a claim only earns trust after someone has tried to break it. I turned that into a LangGraph loop with separate red, blue and judge roles, plus an auditor to stop it running forever. The demo link is a static sample that runs in your browser with no API calls, so it shows the shape of a report and nothing more. For the real thing, read the code or run it with your own key.
