  architecture: "MVC, bent a little to fit Swing's event model. GameEngine owns the random number, the guess checks, the attempt count and the state machine.     - name: "GameUI (JFrame)"

    - name: "InputPanel"

    - name: "FeedbackDisplay"

    - name: "ControlPanel"

  dataFlow: "A new game picks a secret number, resets the attempts and moves to PLAYING. When you submit a guess, InputPanel checks it and fires an ActionEvent. The handler passes the number to GameEngine's validateGuess(), which counts the attempt and returns TOO_HIGH, TOO_LOW or CORRECT. FeedbackDisplay shows the hint and the count. A correct guess moves the game to FINISHED, shows your stats and offers a replay."

  keyDecisions:
    - decision: "Swing over JavaFX"
      rationale: "Swing is mature, well documented and easier to learn for GUI basics. Its simplicity kept my attention on event-driven patterns instead of the framework."
      tradeoff: "Gives up JavaFX's more modern features and look."

    - decision: "A state machine for game flow"
      rationale: "With INITIAL, PLAYING and FINISHED written out, you can't submit a guess after winning or start a second game on top of the first. Overkill for a game this size? Slightly. It also made the behaviour predictable."
      tradeoff: "More code up front: every state and transition is written out rather than implied."

    - decision: "Check input in the UI first"
      rationale: "InputPanel handles numeric input and range checks, so the player hears about bad input right away. GameEngine gets to think only about the game."
      tradeoff: "Checks sit in more than one layer, so changing a rule means changing it in each."

    - decision: "Modal dialogs for wins and replays"
      rationale: "JOptionPane makes the player acknowledge the result before moving on, which also prevents accidental resets."
      tradeoff: "Each dialog blocks the window until dismissed: an extra click at every win or replay."

      title: "The game engine"
      code: |
        public class GameEngine {
            private int secretNumber;
            private int attempts;
            private GameState state;
            private final int MIN_VALUE = 1;
            private final int MAX_VALUE = 100;

            public void startNewGame() {
                this.secretNumber = (int)(Math.random() * MAX_VALUE) + MIN_VALUE;
                this.attempts = 0;
                this.state = GameState.PLAYING;
            }

            public GuessResult validateGuess(int guess) {
                if (state != GameState.PLAYING) {
                    throw new IllegalStateException("No active game");
                }

                attempts++;

                if (guess == secretNumber) {
                    state = GameState.FINISHED;
                    return new GuessResult(ResultType.CORRECT, attempts);
                } else if (guess < secretNumber) {
                    return new GuessResult(ResultType.TOO_LOW, attempts);
                } else {
                    return new GuessResult(ResultType.TOO_HIGH, attempts);
                }
            }
        }

    - language: "java"
      title: "Connecting Swing events to the engine"

        public class GameUI extends JFrame {
            private GameEngine engine;
            private JTextField guessInput;
            private JLabel feedbackLabel;
            private JLabel attemptsLabel;

            private void initializeListeners() {
                submitButton.addActionListener(e -> handleGuessSubmission());
                newGameButton.addActionListener(e -> startNewGame());
            }

            private void handleGuessSubmission() {
                try {
                    int guess = Integer.parseInt(guessInput.getText());

                    if (guess < 1 || guess > 100) {
                        showError("Please enter a number between 1 and 100");
                        return;
                    }

                    GuessResult result = engine.validateGuess(guess);
                    updateFeedback(result);

                    if (result.getType() == ResultType.CORRECT) {
                        handleGameWin(result.getAttempts());
                    }
                } catch (NumberFormatException ex) {
                    showError("Invalid input. Please enter a valid number.");
                } catch (IllegalStateException ex) {
                    showError("Start a new game first!");
                }
            }
        }

        // Advanced input validation preventing non-numeric entry
        public class NumericDocumentFilter extends DocumentFilter {
            @Override
            public void insertString(FilterBypass fb, int offset,
                                    String string, AttributeSet attr)
                                    throws BadLocationException {
                if (string != null && string.matches("\\d+")) {
                    super.insertString(fb, offset, string, attr);
                }
            }

            @Override
            public void replace(FilterBypass fb, int offset, int length,
                               String text, AttributeSet attrs)
                               throws BadLocationException {
                if (text != null && text.matches("\\d*")) {
                    super.replace(fb, offset, length, text, attrs);
                }
            }
        }

        // Applied to input field
        ((AbstractDocument)guessInput.getDocument())
            .setDocumentFilter(new NumericDocumentFilter());

  learnings:
    - insight: "Input arrives whenever it arrives"
      description: "Swing taught me the basics of event-driven code: listeners keep the parts loosely coupled, and control flow runs through callbacks."

    - insight: "Even a small game has state problems"
      description: "Without explicit states, edge cases showed up: guessing before the game had started, starting several games at once, carrying on after winning."

    - insight: "Separation pays off quickly"
      description: "At first I mixed UI code with game logic, and it was brittle and hard to change. Pulling GameEngine out of GameUI meant I could redesign the screen without touching the rules, and the logic no longer needed a UI to test."

    - insight: "Each validation layer catches something different"
      description: "The DocumentFilter gives instant feedback, the range check enforces the rules, and the engine checks the game state. One check on its own is fragile."

    - insight: "Working isn't the same as pleasant"
      description: "Early versions worked but felt clunky. Color-coded hints, confirmation dialogs and immediate input checks made it feel far better."
---
Swing delivers clicks and keystrokes whenever the player feels like it, so the code can't assume anything about what happens next. That's the real lesson hiding in this little game, and it was my practice ground for callbacks, explicit state and keeping game logic out of the window code. The name is slightly misleading, by the way: the accuracy is entirely your job.
