  context: "Speedcubers want a timer that gets out of the way: hit a key to start inspection, release to solve, and immediately see how this solve moved the averages. Most browser timers cover the timing but skip the cube, the scrambles for larger puzzles, or offline use. This project is an attempt at the whole loop in plain JavaScript, with a 3D cube, correct multi-size scrambles, the standard rolling averages, and a WebAssembly solver, all installable and usable without a network."
  architecture: "The app is plain ES modules with no framework. A central state module plus a storage module (localStorage) hold the source of truth: settings, sessions, and solves. Input handling maps keyboard events to cube moves and timer controls. A Three.js layer renders the cube and animates face turns, with a separate dynamic-cube module tracking the logical cube state and a 2D preview. Scramble generation builds a move sequence per puzzle size and applies it to both the logical state and the Three.js cube. The timer module runs inspection and solve timing with penalties and writes finished solves to storage, which the stats module reads to compute best, mean, and rolling averages, rendered by a Chart.js charts module. A WebAssembly module (C++ compiled with Emscripten) is loaded lazily for scramble validation and hints. A PWA layer (service worker plus manifest) caches the app for offline use."

  keyDecisions:
    - decision: "Vanilla JS in 25 modules, no framework"
      reasoning: "The app is mostly direct DOM and Three.js work driven by keyboard input and a small shared state. A framework would add weight and indirection without buying much; plain ES modules with one state and one storage module kept it lean and easy to reason about."
      alternatives: "A React/Vue SPA (heavier, more build complexity for a largely imperative 3D/keyboard app)."
    - decision: "Compile the cube solver in C++ to WebAssembly"
      reasoning: "A solver and scramble validator are compute-heavy and already natural to express in C++. Compiling to WebAssembly with Emscripten runs that logic at near-native speed in the browser, and loading it lazily keeps it off the initial path."
      alternatives: "A pure-JS solver (slower, and a rewrite of logic that already existed in C++); a server-side solver (needs a backend and breaks offline use)."
    - decision: "Offline-first PWA with local persistence"
      reasoning: "Cubers use a timer repeatedly, often without caring about a network. A service worker plus localStorage makes the app installable, fast, and fully usable offline, with JSON/CSV export and import to move data between devices instead of a server account."
      alternatives: "A server-backed app with accounts (network dependency, hosting, and sign-in friction for a single-user tool)."
  codeSnippets:
    - title: "Lazy-load the WASM solver, degrade if it is missing"
      language: "javascript"
      code: |
        let wasmModule = null;

        export const loadSolverModule = async () => {
          if (wasmModule !== null) return wasmModule;
          try {
            const moduleFactory = (await import("./solver.js")).default;
            wasmModule = await moduleFactory();   // Emscripten module factory
            return wasmModule;
          } catch (error) {
            console.warn("WASM solver not available.", error);
            wasmModule = null;
            return null;
          }
        };
      explanation: "The C++ solver is compiled to WebAssembly and loaded only when needed. If the module fails to load, the loader returns null and the UI falls back to a clear message instead of breaking, the same degrade-gracefully approach used for optional features."

A keyboard-first speedcubing app built in vanilla JavaScript as 25 ES modules. It renders a Rubik's Cube in 3D with Three.js, generates WCA-style scrambles for 2x2 through 7x7, times solves with inspection and +2/DNF penalties, and keeps the averages cubers care about, best, mean, and rolling Ao5/Ao12/Ao100, with a PB timeline and Chart.js charts. A C++ cube routine compiled to WebAssembly handles scramble validation and hints, and the whole thing runs offline as an installable PWA with local persistence and JSON/CSV export.
