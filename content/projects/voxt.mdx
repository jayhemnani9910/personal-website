challenge: "The repo's own brief says it best: the user thinks in Gujarati, Hindi or Sindhi, types in English, and speaking is faster than typing. So plain dictation isn't enough, because Devanagari or Gujarati script is no use in an English keyboard workflow. And a global hotkey on Wayland is its own puzzle, since X11 hotkey libraries don't work there."
solution:
  - "Whisper (whisper-large-v3, hosted on Groq) detects the language and transcribes it."
  - "Every transcript then goes through a Groq-hosted Llama model. English stays as it is. Hindi or Gujarati comes back in Latin letters, with an English translation after a --- line. If that step fails, you get the raw transcript."
  - "The hotkey reads /dev/input directly (evdev), below the display server, so Wayland can't get in its way. The clipboard uses wl-copy on Wayland and falls back to an X11 clipboard library."
  - "It lives in the tray: beeps on start and stop, the icon turns red while recording, and a desktop notification shows the text. Each transcript goes into SQLite, and the audio is kept as a WAV file."
impact:
  - "Dictation becomes one key, F9 by default and configurable to any of F1 to F12, with no window to focus."
  - "Rate limits and 503s retry up to 3 times with backoff, so a brief limit doesn't cost you the recording."
  - "The trade-offs: it needs a Groq API key and a network, your audio goes to Groq, and the hotkey needs your user in the input group. There are no tests yet, and the docs target Wayland on GNOME, so X11 is the less-travelled path."

The neat part is the rule for mixed speech. "The meeting is at 3pm" stays exactly as it is, while "kem cho bhai" stays in Latin letters and gets "How are you brother" underneath. That behaviour comes from a short prompt with examples, and if the call fails you still get the raw transcript.
