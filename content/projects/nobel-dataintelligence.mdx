challenge: "Most protein models treat a protein as a sequence or a frozen structure, but proteins move. Does adding that motion actually help predict stability and enzyme speed? Testing that meant trusting the vibration feature first, and for a while a unit bug had collapsed every protein's spectrum to a single spike at 0 cm^-1 with nothing complaining. Finding that bug became part of the project."
solution:
  - "The model looks at three views of a protein: ProtT5 for sequence, a 1D SpectralCNN over a vibrational density-of-states (VDOS) spectrum for motion, and ChemBERTa plus reaction fingerprints for the substrate."
  - "The VDOS spectrum comes from normal mode analysis with ProDy, which treats the protein as a network of springs. The result is a 1000-point spectrum that sequence and chemistry models never see."
  - "A small gating network weights the three branches for each prediction, and returns those weights so you can inspect them."
  - "MM-Drop training randomly blanks the spectral branch, so the model can still give an answer when no structure is available."
  - "Then I went after the claim itself: fixed the units bug in both VDOS paths, fixed an ablation runner whose 4 rows included 3 identical ones, and ran a controlled thermophile vs mesophile test."

deepDive:
  context: "Whether a protein is stable, and how fast an enzyme works, may depend partly on how it moves. Motion is awkward to express as a feature, so most models leave it out. This project asks whether a vibrational spectrum from normal mode analysis adds anything when combined with sequence and chemistry. The Quantum Data Decoder core holds the normal mode analysis, spectra, encoders, fusion and training. VibroPredict builds on it to predict log(k_cat), a measure of enzyme turnover. So far, the answer to the question is \"no evidence yet\"."
  architecture: "Three encoders feed one fusion layer: ProtT5 on sequence, a SpectralCNN on the VDOS spectrum, and ChemBERTa plus fingerprints on substrate SMILES. The spectrum is made upstream. A structure goes through ANM or GNM normal mode analysis, the eigenvalues become vibrational frequencies, and Lorentzian broadening smooths them into 1000 points. TriModalFusion projects the branches to a shared size and combines them using softmax gate weights. A regression head then predicts log(k_cat) and returns the gates alongside it. The core also has GATv2 and CNN encoders and Novozymes and CAFA5 loaders for the stability and function tasks. The bundled Kaggle data is a 4-row placeholder, so those pipelines only prove the plumbing."

  keyDecisions:
    - decision: "Add a vibrational (VDOS) feature as a third input"
      reasoning: "Sequence and chemistry are standard inputs, and motion isn't. Normal mode analysis gives a cheap spectrum from a structure. That was the hypothesis. The controlled test didn't support it, and the likely weak spot is that a single static snapshot with a uniform spring network throws away too much."
      alternatives: "Sequence and chemistry only (simpler, ignores motion); full molecular dynamics (far too expensive per protein across a dataset)."
    - decision: "Gated fusion instead of plain concatenation"
      reasoning: "The three inputs may not be equally useful for every protein, and one can be missing. Gating lets the model weight them per sample and shows you the weights. Whether this beats concatenation hasn't been measured."
      alternatives: "Concatenate-and-MLP (no per-sample weighting), bilinear fusion (more parameters, harder to read)."
    - decision: "MM-Drop: randomly drop the spectral branch during training"
      reasoning: "VDOS needs a structure, and you don't always have one. Blanking the branch during training pushes sequence and chemistry to work alone, so a query with no structure still returns a prediction. How good that prediction is remains unmeasured."
      alternatives: "Require all three inputs (brittle), or train separate single-input models (loses the fusion)."
  codeSnippets:
    - title: "Gated fusion: weighing each branch per sample"
      language: "python"
      code: |
        concat = torch.cat([h_seq, h_spec, h_chem], dim=-1)
        gates = torch.softmax(self.gate_net(concat), dim=-1)  # (batch, 3)

        proj_seq = self.proj_seq(h_seq)
        proj_spec = self.proj_spec(h_spec)
        proj_chem = self.proj_chem(h_chem)

        fused = (
            gates[:, 0:1] * proj_seq
            + gates[:, 1:2] * proj_spec
            + gates[:, 2:3] * proj_chem
        )
        return self.dropout(fused), gates
      explanation: "A small network reads all three embeddings and outputs a weight for each. The gates are returned too, so you can see which branch a prediction leaned on."

        # GNM eigenvalues are proportional to omega^2 -> frequencies in cm^-1

        frequencies = np.sqrt(np.maximum(eigenvalues, 0)) * conversion_factor

        generator = SpectralGenerator(
