# /youtube Channel Showcase Page — Design

Date: 2026-07-19
Status: Approved by Jay (conversation, 2026-07-19)

## Purpose

A new page on jayhemnani.me that showcases Jay's two YouTube channels, with an
about section per channel and a Videos / Shorts / Live tab bar. Data is
committed JSON refreshed later by a daily skill (out of scope here; this design
makes it a one-file job).

## Decisions locked with Jay

1. **Data source:** committed JSON (`src/data/youtube.json`), regenerated by a
   fetch script. No runtime YouTube API dependency, no API key. The existing
   OAuth refresh tokens in `~/projects/personal/jh-analytics/stream/secrets/`
   authenticate the fetch (public-data endpoints only).
2. **Channels:** both channels on one page:
   - `JH-Analytics | 2.0` (`@jhanalytics2.0`, UCSf0pNIEkJgXhH7WzIsFnpw) — AI news channel. Default selected.
   - `JH-Analytics` (`@jhanalytics`, UCRAV0VDSxngptEo5SY4nKcw) — analytics + FC gaming channel.
3. **Layout:** channel switcher at the top swaps the whole view (about, stats,
   tabs) between the two channels.
4. **Nav:** masthead entry labeled `Channel` → `/youtube` (sixth entry, after FDE).
5. **Click action:** cards open the video on YouTube in a new tab. No embeds.
6. **Content split:** YouTube auto-playlists per channel: `UULF<id-suffix>` =
   long-form, `UUSH<suffix>` = shorts, `UULV<suffix>` = live. No duration
   heuristics.

## Data contract (the interface every piece codes against)

`src/data/youtube.json`, validated by Zod in `src/lib/youtube.ts`:

```ts
type YouTubeItem = {
  id: string;                 // YouTube video id
  title: string;
  publishedAt: string;        // ISO 8601
  durationSec: number;        // 0 allowed for upcoming/live
  views: number;
  thumb: string;              // https://i.ytimg.com/... (script-resolved)
  status?: "live" | "upcoming"; // only set on live-tab items; absent = past
};

type YouTubeChannel = {
  id: string;                 // UC...
  title: string;
  handle: string;             // "@jhanalytics2.0"
  url: string;                // https://www.youtube.com/@jhanalytics2.0
  stats: { subscribers: number; views: number; videos: number };
  videos: YouTubeItem[];      // latest long-form, max 12
  shorts: YouTubeItem[];      // latest shorts, max 12
  live: YouTubeItem[];        // live/upcoming first, then latest past, max 12
};

type YouTubeData = {
  fetchedAt: string;          // ISO 8601
  channels: YouTubeChannel[]; // exactly 2; [0] = @jhanalytics2.0 (AI, default), [1] = @jhanalytics
};
```

Authored copy (taglines, about paragraphs) lives in the page component, NOT in
the JSON, so the daily refresh can never overwrite Jay's words.

## Components

### 1. Fetch script — `scripts/fetch-youtube.mjs`

Plain Node (>=20), zero npm dependencies (global `fetch`).

- Reads `client_secret.json` + `token.json` from
  `/home/po/projects/personal/jh-analytics/stream/secrets/` (one token is
  enough; all queried data is public).
- Refreshes the access token via POST `https://oauth2.googleapis.com/token`
  (`grant_type=refresh_token`).
- Per channel (both queried with one bearer token, by channel id):
  - `channels.list(part=snippet,statistics, id=...)` → title, handle, stats.
  - `playlistItems.list(playlistId=UULF/UUSH/UULV..., maxResults=12)` per tab;
    a 404 for an empty auto-playlist is caught and yields `[]`.
  - `videos.list(part=snippet,contentDetails,statistics,liveStreamingDetails, id=<batch>)`
    → durations (parse ISO 8601 duration to seconds), view counts, and
    `snippet.liveBroadcastContent` (`live` / `upcoming` / `none`) for status.
- Thumbnails: default `https://i.ytimg.com/vi/<id>/hqdefault.jpg`. For shorts,
  HEAD-check `https://i.ytimg.com/vi/<id>/oardefault.jpg` (vertical variant);
  use it if it returns 200, else fall back to hqdefault.
- Sorts live tab: `live` first, then `upcoming`, then past by publishedAt desc.
- Writes pretty-printed JSON to `src/data/youtube.json` (stable key order, so
  daily diffs stay reviewable).
- Fails loudly (non-zero exit, plain-English message) on any API error; never
  writes a partial file.
- Quota: ~12 units per run.

Run: `node scripts/fetch-youtube.mjs` from the repo root.

### 2. Schema + loader — `src/lib/youtube.ts`

- Zod schemas mirroring the data contract exactly (`YouTubeDataSchema` etc.),
  following the style of `src/lib/definitions.ts`.
- `getYouTubeData(): YouTubeData` — imports the JSON, parses with the schema,
  throws on mismatch (build fails; a bad skill run can never deploy).
- Exported helpers: `formatViews(n)` (1.2K / 54K style), `formatDuration(sec)`
  (m:ss / h:mm:ss), `formatDate(iso)` (matches site conventions).

### 3. Test — `src/lib/youtube.test.ts`

Vitest, style of existing `src/lib/*.test.ts`:
- committed `youtube.json` passes the schema;
- exactly 2 channels, `[0]` is `@jhanalytics2.0`;
- every item's `thumb` is an `https://i.ytimg.com/` URL;
- formatter helpers' edge cases (0 views, >1h duration).

### 4. UI — `src/components/YouTubeShowcase.tsx` (`'use client'`)

TWO READERS language throughout (`--tr-*` tokens, serif = Jay's voice, mono =
machine data, depth = surface + hairline, no shadows/glows).

- **Channel switcher**: segmented control, two buttons (`aria-pressed`), each
  showing channel title + mono handle. Selecting swaps everything below.
- **About block**: authored serif copy per channel (2–3 sentences, provided in
  this spec, style-filter compliant) + mono stat row: SUBSCRIBERS / VIEWS /
  UPLOADS + a mono "data as of <fetchedAt date>" line.
- **Tab bar**: Videos / Shorts / Live — accessible tablist copied from
  `src/app/lab/page.tsx` (roving tabindex, ArrowLeft/ArrowRight, `role=tab`/
  `tabpanel`). Active tab underline is the page's ember accent.
- **Cards**: link (`target="_blank" rel="noopener noreferrer"`) to
  `https://www.youtube.com/watch?v=<id>` (shorts: `/shorts/<id>`).
  - Videos + Live: 16:9 `next/image` thumbnail grid (3-across desktop, 1-col
    mobile), serif title, mono meta line `views · date · duration`.
  - Shorts: 9:16 cards in a denser grid (4–6 across desktop, 2 across mobile).
  - Live items with `status`: ember `LIVE` / `UPCOMING` badge (the page's only
    other ember use). Past streams stay neutral.
- Empty tab → quiet mono line ("No uploads here yet.").
- Motion: at most a `Reveal` on section entry via the existing motion kit;
  everything gated by `usePrefersReducedMotion()`. Tab/channel switches are
  instant (no animation needed).
- Mobile: thumbnails inside `min-w-0`-safe containers; no horizontal page
  scroll.

### 5. Page — `src/app/youtube/page.tsx` (server component)

- Loads data via `getYouTubeData()`, renders `EditorialMasthead` +
  `<main id="main-content">` + h1 + `YouTubeShowcase` + `EditorialColophon`,
  following the structure of `/lab`.
- `generateMetadata()`: title "Channel", description mentioning both channels.
- Heading order: one h1, section h2s, card titles h3 — no level skips.
- If `src/app/sitemap.ts` exists, add `/youtube`.

### 6. Config + nav (small diffs)

- `next.config.ts`: add `{ protocol: "https", hostname: "i.ytimg.com" }` to
  `images.remotePatterns`. (Approved by Jay via this design.)
- `src/components/EditorialMasthead.tsx`: append
  `{ href: "/youtube", label: "Channel", section: "channel" }` to `NAV_LINKS`.

## Error handling

- Fetch script: any API failure → non-zero exit, no file written.
- Build: schema mismatch in committed JSON → build fails, previous deploy
  stays live.
- UI: empty arrays render the quiet empty state; missing `status` = past.
- Thumbnails: script-resolved URLs; if YouTube 404s a thumb after commit,
  `next/image` shows alt text until the next daily run corrects it.

## Testing / verification

- `npm run test:run` (new youtube test + existing suite, incl. tokens test).
- `npm run lint`, `npm run build` (no server running during build).
- Manual: both channels × three tabs, both themes, mobile width (no horizontal
  scroll), keyboard-only tab navigation, Lighthouse a11y spot-check.
